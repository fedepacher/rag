# Fully pinned dependency lock for the `rag` service (Dockerfile-combined).

# WHY A FULL LOCK: this file previously declared 16 unpinned names. That is not a
# dependency list, it is a bet that every upstream project stays compatible forever.
# It already cost us once: LangChain 1.0 removed `langchain.chains`, `langchain.llms`
# and `langchain.prompts`, which this repo imports throughout, so a fresh build would
# resolve to a version the code cannot run on.
#
# DIRECT DEPENDENCIES (everything else below is a transitive of these):
#   pymongo pypdf2 python-docx requests typing_extensions
#   langchain langchain-community langchain-core langgraph
#   chromadb gpt4all faiss-cpu openai tiktoken
#   pytest
#
# pytest is back (it was removed when this file was pinned, because it shipped a test
# dependency into the production image for tests that did not exist). tests/ now exists:
# the CRAG/Self-RAG graph routing is pure state -> node-name logic, so its acceptance
# criteria are checkable in under a second instead of through a 1h47m pipeline run.
# Running them needs the real langgraph/langchain imports, which is why they run in this
# image. It stays in the runtime lock rather than a separate dev file because there is
# no separate dev image to install it into.
#
# langgraph is held below 0.4: it is the newest line that still declares
# langchain-core < 0.4, so it cannot drag the stack past the LangChain 1.0 break.
#

#   sentence-transformers, transformers  -> pulled torch + 20 nvidia CUDA wheels +
#       triton, 5.5 GB of GPU runtime on a CPU-only target box. Embeddings come from
#       GPT4AllEmbeddings and inference from Ollama over HTTP; LLMProcessorHuggingFace
#       posts to a remote endpoint and runs nothing locally.
#   langchain-ollama, langchain-openai   -> the code imports langchain.llms.Ollama and
#       langchain.chat_models.ChatOpenAI, which live in langchain / langchain-community.
#   pypdf2 (duplicate entry)

#   undeclared and arriving only by accident as transitives.
